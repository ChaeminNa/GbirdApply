# G-Bird 지원서 (GbirdApply)

KAIST 배드민턴 동아리 **G-Bird**의 신입 부원 지원서 웹앱입니다. 지원자는 링크 하나로 지원서를 작성/수정하고 면접·참석 여부를 확인하며, 운영진은 같은 화면에서 지원자 목록을 확인하고 면접 시각·합격 여부를 입력합니다.

- 프런트엔드: 이 저장소의 **`index.html` 하나뿐**입니다. 별도의 빌드 과정이 없고, 그냥 정적 파일로 아무 곳에나 올려서(GitHub Pages 등) 열면 동작합니다.
- 백엔드/데이터베이스: **Google Apps Script + Google 스프레드시트**. 별도 서버나 DB가 없습니다. 지원자 데이터는 전부 스프레드시트 안에 있습니다.

> ⚠️ 이 파일(`index.html`)은 손으로 직접 고치는 파일이 아닙니다. 아래 "이 파일의 정체" 섹션을 꼭 읽어주세요.

## 지원자 화면 흐름

1. **랜딩 화면** → "지원하기" 또는 "지원 확인/수정"
2. **로그인 게이트**: 이름 + 전화번호로 본인 확인 (지원 시에는 신규 작성, 확인 시에는 기존 지원서 조회)
3. **지원서 작성/수정**: 성함, 성별, 전화번호, 이메일, 생년월일, 학과/학위/재학학기, 배드민턴 경험, 참여 가능 시간, 취미, 유입 경로, 하고 싶은 말
4. **내 지원 현황(`me`) 화면**: 제출 완료 확인, 면접 시각 확인, **참석 여부(RSVP) 응답**, 불참/변경 사유 입력, (공개 시점 이후) 합격 여부 확인
5. 마감/면접시각 공개/결과 공개 시점은 운영진이 설정한 날짜·시각(`close`, `reveal`, `result`)을 기준으로 화면에 노출 여부가 결정됩니다.

## 운영진(관리자) 화면 흐름

- 랜딩에서 관리자 진입 → 관리자 비밀번호 입력 (앱에 해시로만 저장되어 있고 평문은 코드에 없음)
- **설정(setup) 탭**: 시즌 선택(연도 + 봄/가을), Google Sheet 연동 주소 입력, Apps Script 코드 복사, 모집 일정(면접일, 마감, 시각 공개, 결과 공개 시각) 설정, 시즌 발행(publish)
- **목록 탭**: 지원자 목록 조회, 면접 시각·합격 여부 입력, CSV 다운로드
- 로컬 저장 데이터와 시트를 동기화(`sync`)하는 기능 있음 — **시트가 항상 source of truth**(최근 커밋 `a927190`에서 정리됨)

## 이 파일의 정체 (매우 중요)

`index.html`은 **Claude Design 캔버스에서 내보낸(export) 번들 파일**입니다. 직접 만든 순수 HTML/JS가 아니라, 다음 구조로 되어 있습니다.

```
<script type="__bundler/manifest">      각종 리소스(이미지 등) base64 매니페스트
<script type="__bundler/ext_resources"> React/ReactDOM 등 외부 스크립트 URL 목록
<script type="__bundler/page_order">    페이지 순서 (현재 빈 배열)
<script type="__bundler/template">      실제 페이지 전체가 JS 문자열(JSON)로 이스케이프되어 들어있음
```

즉 실제 화면 마크업/스타일/로직은 `__bundler/template` 안에 **문자열로 인코딩되어** 들어 있고, 그 안에서도 Apps Script 백엔드 코드(`doGet`/`doPost` 등)는 다시 **문자열 배열**(`const APPS_SCRIPT = [...]`)로 한 번 더 감싸져 있습니다. 이 문자열이 관리자 화면의 "Apps Script 코드 복사" 버튼으로 클립보드에 복사됩니다.

**따라서:**

- `index.html`을 텍스트 에디터로 직접 열어 로직을 고치는 것은 사실상 불가능합니다(줄바꿈이 이스케이프된 하나의 거대한 JSON 문자열이며, 파일 크기도 ~7.8MB입니다).
- UI/로직을 바꾸려면 **Claude Design 캔버스(원본 `.dc.html` 아트보드)에서 편집한 뒤 다시 이 형태로 export**해야 합니다. 원본 캔버스가 없다면, 이 저장소의 커밋 기록이 사실상 유일한 변경 이력입니다.
- Apps Script 백엔드 코드를 고치고 싶다면, 관리자 화면의 "Apps Script 코드 복사" 버튼으로 원문을 꺼내거나, 이 README 작성 시점 기준으로 `index.html`의 `__bundler/template` 안, `const APPS_SCRIPT = [...]` 부분을 찾아 수정한 뒤 다시 export해야 합니다.

## Google Apps Script 백엔드

지원 페이지 관리자 화면의 "Apps Script 코드 복사" 버튼으로 나오는 코드가 전체 백엔드입니다. 요약:

### 배포 방법 (백엔드 코드 안 주석에도 있음)
1. 새 Google 스프레드시트 생성 → 확장 프로그램 > Apps Script
2. 기존 내용 지우고 복사한 코드 전체 붙여넣기 → 저장
3. 배포 > 새 배포 > 유형 [웹 앱] / 실행 [나] / 액세스 [모든 사용자] > 배포
4. 나온 `.../exec` 주소를 지원 페이지 운영진 화면의 "Apps Script 웹 앱 주소"에 입력
5. Apps Script 편집기 > 프로젝트 설정(톱니바퀴) > 스크립트 속성에서 `ADMIN_TOKEN` 값을 32자 이상의 임의 문자열로 추가 → 같은 값을 지원 페이지 관리자 화면의 "관리자 토큰" 입력칸에도 입력

### 시트 구조
시즌마다 별도 시트 탭(예: `2026fall`)이 자동 생성되며, 컬럼은 다음과 같습니다.

|---|------|------|
| 1 | 성함 | |

| 4 | 이메일 | |
| 5 | 생년월일 | 텍스트 형식 강제 |
| 6 | 학과/학위 및 재학학기 | |

| 8 | 참여 가능 | |

| 11 | 하고 싶은 말 | |

### `doPost` 액션 목록 (`body.action`)
- `submit` — 신규 지원서 제출. 전화번호 기준 30초 캐시 레이트리밋(`sub_<phone>`) + 중복 지원 차단
- `update` — 기존 지원서 수정 (전화번호로 행 탐색)
- `lookup` — 전화번호로 본인 지원서 조회 (인증 불필요)
- `rsvp` — 참석 여부/사유 갱신 (인증 불필요, 전화번호 기반)
- `admin` — 운영진이 특정 지원자의 면접시각/합격여부 입력 (`ADMIN_TOKEN` 필요)
- `list` — 전체 지원자 목록 조회 (`ADMIN_TOKEN` 필요)
- `info` — 연결된 시트 파일명/URL/행 수 등 조회 (`ADMIN_TOKEN` 필요)
- `publish` — 발행할 시즌 지정, 스크립트 속성 `PUBLISHED_SEASON`에 저장 (`ADMIN_TOKEN` 필요)
- `published` — 현재 발행된 시즌 조회 (인증 불필요)

인증은 요청 바디의 `token` 값이 스크립트 속성 `ADMIN_TOKEN`과 일치하는지만 확인하는 단순 방식입니다(`isAdmin_`).

### 새 시즌을 여는 방법
코드 수정 없이 가능합니다.
1. 관리자 화면 설정 탭에서 연도 + 봄/가을 선택 (시즌 키는 `{연도}{spring|fall}` 형식, 예: `2026fall`)
2. 같은 시트 파일 안에 새 시즌 이름의 탭이 자동 생성됩니다 (`seasonSheet_`, `sheet_` 함수)
3. 모집 일정(면접일/마감/공개 시각) 입력 후 "발행(publish)" 하면 그 시즌이 지원자에게 노출되는 기본 시즌이 됩니다.

⚠️ 프런트엔드 쪽 기본값(`DEFAULT_SEASON`, `KEY = 'gbird-2026-fall'` 등 로컬 저장 키 이름)은 캔버스 편집을 통해서만 바뀌므로, 시즌이 바뀔 때마다 이 상수들이 실제로 갱신되는지는 캔버스 편집자가 확인해야 합니다.

## 알아두어야 할 설계/이력상 특이사항

- **시트가 source of truth**: 로컬(localStorage)에 캐시된 지원자 데이터와 시트가 다르면 로그인 시 항상 시트 기준으로 재동기화합니다 (`a927190`).
- **쓰기 실패 시 데이터 유실 방지**: 지원서 제출/수정/RSVP 요청이 실패해도 사용자가 입력한 내용이 조용히 사라지지 않도록 최근에 수정되었습니다 (`8cc86b0`). 백엔드가 일시적으로 응답하지 않아도 사용자 입력이 날아가지 않는지 배포 전 확인하세요.
- **크로스 브라우저 이슈**: 카카오톡 인앱 브라우저 등 일부 환경에서 지원 조회가 깨졌던 이력이 있습니다 (`e72e365`). 새 기능 추가 시 인앱 브라우저(카카오톡, 인스타그램 등)에서도 반드시 테스트하세요.
- **관리자 비밀번호 vs 관리자 토큰**: 둘은 다른 메커니즘입니다.
  - "관리자 비밀번호"는 프런트엔드 로컬 게이트(해시값만 코드에 존재, `ADMIN_HASH`)로, 관리자 화면 진입을 막는 용도입니다.
  - "관리자 토큰"(`ADMIN_TOKEN`)은 Apps Script 스크립트 속성에 저장되며, 실제 쓰기/조회 API 호출을 인가하는 값입니다. 둘 다 관리자 인수인계 시 함께 전달해야 합니다.
- Apps Script 웹앱 배포 URL은 재배포할 때마다 바뀔 수 있어 여러 번 업데이트된 이력이 있습니다 (`54da564`, `88db0ed`, `32b76f7` 등). URL이 바뀌면 관리자 화면의 "Apps Script 웹 앱 주소"에 새 값을 다시 입력해야 합니다.
