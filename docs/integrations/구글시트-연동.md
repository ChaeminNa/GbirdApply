# 구글 스프레드시트 연동

프런트엔드는 Apps Script 웹 앱(`.../exec`)에 `POST`로 JSON을 보내는 방식으로만 스프레드시트와 통신합니다. 별도 서버나 DB는 없습니다.

## 시트 구조

시즌마다 별도 시트 탭(예: `2026fall`)이 자동 생성되며, 컬럼은 다음과 같습니다.

| # | 컬럼 | 비고 |
|---|------|------|
| 1 | 성함 | |
| 2 | 성별 | |

| 4 | 이메일 | |
| 5 | 생년월일 | 텍스트 형식 강제 |
| 6 | 학과/학위 및 재학학기 | |
| 7 | 배드민턴 경험 | |
| 8 | 참여 가능 | |
| 9 | 취미 | |
| 10 | 유입 경로 | |
| 11 | 하고 싶은 말 | |
| 12 | 제출시각 | 텍스트 형식 강제 |

## `doPost` 액션 목록 (`body.action`)

| 액션 | 설명 | 인증 |
|---|---|---|
| `submit` | 신규 지원서 제출. 전화번호 기준 30초 캐시 레이트리밋 + 중복 지원 차단 | 불필요 |
| `update` | 기존 지원서 수정 (`oldPhone`으로 행 탐색) | 불필요 |
| `lookup` | 전화번호로 본인 지원서 조회 | 불필요 |
| `rsvp` | 참석 여부/사유 갱신 (전화번호 기반) | 불필요 |
| `admin` | 특정 지원자의 면접시각/합격여부 입력 | `ADMIN_TOKEN` 필요 |
| `list` | 전체 지원자 목록 조회 (전화번호가 빈 행은 제외) | `ADMIN_TOKEN` 필요 |
| `info` | 연결된 시트 파일명/URL/행 수 등 조회 (관리자 화면 상단의 "구글 시트에서 열기" 버튼이 사용) | `ADMIN_TOKEN` 필요 |
| `publish` | 발행할 시즌 지정, 스크립트 속성 `PUBLISHED_SEASON`에 저장 | `ADMIN_TOKEN` 필요 |
| `published` | 현재 발행된 시즌 조회 | 불필요 |

인증은 요청 바디의 `token` 값이 스크립트 속성 `ADMIN_TOKEN`과 일치하는지만 확인하는 단순 방식입니다(`isAdmin_` 함수). 코드 자체는 모두 `index.html`에 내장되어 있습니다 — 수정 방법은 [`../setup/02-index-html-직접-수정.md`](../setup/02-index-html-직접-수정.md).

## 쓰기 동작 원칙

- 새 지원서(`submit`)는 항상 시트에서 **내용이 있는 마지막 행 다음**에 추가됩니다(`appendRow`). 중간에 빈 행이 있어도 그 자리에 끼워 넣지 않습니다.
- `update`/`rsvp`/`admin`은 전화번호로 찾은 **그 행만** 덮어씁니다. 행을 지우거나 비우는 코드는 어디에도 없습니다 — 시트에 빈 행이 보인다면 시트를 직접 편집(Delete 키로 셀만 지움)한 결과이지, 코드가 만든 게 아닙니다.
- `list`는 전화번호가 빈 행을 걸러내므로, 시트를 직접 편집해 생긴 빈 행은 관리자 화면 목록에 나타나지 않습니다.
