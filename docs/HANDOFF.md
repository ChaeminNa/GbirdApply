# G-Bird 지원 사이트 — 서버 이전 작업 지시서

Claude Code에 이 파일을 그대로 붙여넣고 시작하세요.

---

## 배경

KAIST 대학원생 배드민턴 동아리 G-Bird의 신입 부원 모집 사이트입니다.
현재 완성되어 운영 중이며, **다음 학기에도 재사용**할 예정입니다.

- 저장소: `ChaeminNa/GbirdApply` (public)
- 배포: GitHub Pages → `https://chaeminna.github.io/GbirdApply/`
- 현재 파일: `index.html` 단일 파일 (7.5MB, 모든 자산 인라인)

## 현재 구조와 문제

지원자 데이터는 Google Sheets에 저장되고, Apps Script 웹 앱이 API 역할을 합니다.
`index.html`이 그 주소를 직접 호출합니다.

```
브라우저(index.html) ──fetch──> Apps Script /exec ──> Google Sheets
```

**문제 1 — Apps Script 주소가 클라이언트에 노출됩니다.**
`index.html`에 `const SHEET_URL = 'https://script.google.com/macros/s/.../exec'`가
평문으로 들어 있고, 저장소가 public이라 누구나 볼 수 있습니다.

**문제 2 — 전체 명단이 모든 방문자에게 내려갑니다.**
`{action:'list'}`를 호출하면 인증 없이 전 지원자의 이름·전화번호·이메일·생년월일·
학과·합격 여부가 JSON으로 반환됩니다. 클라이언트가 받아서 화면에서 골라 보여주는 구조입니다.

**문제 3 — 운영진 인증이 클라이언트에서만 이루어집니다.**
비밀번호를 FNV 계열 해시로 비교하는데, 통과 여부가 화면 표시만 좌우합니다.
데이터 접근 자체는 막지 않습니다.

**문제 4 — 합격 여부가 발표 전에도 브라우저에 내려옵니다.**
`localStorage`(키: `gbird-2026-fall`)에 저장되므로 발표 전에 확인이 가능합니다.

**문제 5 — 매 학기 수작업이 필요합니다.**
Apps Script를 재배포하면 `/exec` 주소가 바뀌고, `index.html`의 상수를 고쳐
다시 빌드·업로드해야 합니다.

## 목표

Cloudflare Workers + D1로 이전합니다. 무료 티어로 충분합니다.

```
브라우저 ──fetch /api/*──> Cloudflare Worker ──> D1 (SQLite)
                              │
                              └─ 비밀값은 Worker 환경변수 (브라우저에 노출 안 됨)
```

**반드시 지켜야 할 것**

1. 어떤 응답도 요청자 본인의 레코드를 넘어서는 데이터를 포함하지 않습니다.
   전체 명단은 운영진 인증을 통과한 요청에만 반환합니다.
2. 운영진 인증은 **서버에서** 수행합니다. 비밀번호(또는 그 해시)는 Worker
   환경변수(secret)에 두고, 클라이언트 코드에는 어떤 형태로도 두지 않습니다.
3. 합격 여부는 **발표 시각 이후에만** 응답에 포함합니다. 시각 판정은 서버에서
   `Asia/Seoul` 기준으로 합니다. 클라이언트를 신뢰하지 않습니다.
4. 면접 시각도 같은 방식으로 공개 시각 이후에만 반환합니다.
5. 클라이언트의 `localStorage` 사용을 없애거나, 남기더라도 서버 응답의 사본으로만
   씁니다. 서버 응답이 원본입니다.

## API 설계 (제안 — 더 나은 안이 있으면 바꿔도 됩니다)

모두 `POST /api/...`, 본문은 JSON.

| 엔드포인트 | 인증 | 동작 |
|---|---|---|
| `/api/submit` | 없음 | 지원서 제출. 같은 전화번호가 이미 있으면 409 |
| `/api/me` | 이름 + 전화번호 | 본인 레코드 1건. 면접 시각·합격 여부는 공개 시각 판정 후 포함 |
| `/api/me/update` | 이름 + 전화번호 | 접수 마감 전에만 본인 지원 내용 수정 |
| `/api/me/rsvp` | 이름 + 전화번호 | 참석/불참 + 사유 저장 |
| `/api/admin/login` | 비밀번호 | 성공 시 짧은 수명의 세션 토큰 발급 (HttpOnly 쿠키 권장) |
| `/api/admin/list` | 세션 토큰 | 전체 명단 |
| `/api/admin/set` | 세션 토큰 | 특정 지원자의 면접 시각·합격 여부 수정 |
| `/api/admin/settings` | 세션 토큰 | 공통 설정(날짜·장소·공개 시각) 읽기/쓰기 |
| `/api/settings` | 없음 | 지원자 화면에 필요한 공개 설정만 (비밀값 제외) |

레이트 리밋을 걸어주세요. 특히 `/api/me`는 이름+전화번호만으로 열리므로
무작위 대입이 가능합니다. IP당 분당 시도 횟수를 제한하고, 실패가 반복되면 지연을 주세요.

## 데이터 모델

현재 시트 열 순서 그대로 옮기면 됩니다.

```
이름, 성별, 전화번호, 이메일, 생년월일, 학과/과정,
배드민턴 경력, 정모 참석 가능 여부, 취미, (미사용), 남기실 말,
제출시각, 면접시각, 참석여부, 참석확인시각, 불참/변경 사유, 합격여부
```

- 전화번호가 사실상의 고유 키입니다. 정규화(숫자만 남김) 후 비교합니다.
- 설정값(면접 날짜·장소·공개 시각·발표 시각)은 별도 테이블 또는 KV에 둡니다.
- 기존 Google Sheets의 데이터를 D1로 옮기는 일회성 스크립트가 필요합니다.
  (이번 학기 데이터는 몇 건뿐이라 CSV 내보내기 → import로 충분합니다.)

## 프런트엔드 작업

`index.html`은 **재작성하지 마세요.** 지금 디자인과 화면 흐름이 확정된 상태입니다.
데이터를 주고받는 부분만 교체합니다.

찾아야 할 지점:
- `const SHEET_URL = ...` — 삭제하고 `/api` 상대 경로로 대체
- `api(payload)` 메서드 — 엔드포인트별 호출로 분리
- `syncNow()` — `/api/admin/list` 호출로 변경
- `login()` — `/api/me` 호출로 변경
- `adminLogin` 핸들러의 해시 비교 — `/api/admin/login` 호출로 변경
- `ADMIN_HASH` 상수 — 삭제
- `resultPassed()` / `revealPassed()` — 서버가 이미 판정한 결과를 쓰도록 단순화
  (운영진용 미리보기 토글은 남겨도 됩니다)
- `localStorage` 관련 (`KEY`, `SKEY`, `persist()`) — 서버 응답 기준으로 정리

화면 흐름·문구·레이아웃은 그대로 유지해주세요.

## 배포

1. Worker를 GitHub 저장소와 연결해 `main` 푸시 시 자동 배포되게 합니다.
2. 정적 파일(`index.html`)도 같은 Worker에서 서빙하면 `/api`가 동일 출처가 되어
   CORS 문제가 사라집니다. Cloudflare Pages + Functions 조합도 좋습니다.
3. 비밀값은 `wrangler secret put`으로 넣습니다. 저장소에 커밋하지 않습니다.
4. 기존 GitHub Pages는 새 주소가 확인된 뒤에 정리합니다.
   **포스터 QR이 현재 GitHub Pages 주소를 가리키고 있으니**, 주소가 바뀌면
   그 주소에서 새 주소로 넘겨주는 처리가 필요합니다.

## 매 학기 재사용

다음 학기에 코드 수정 없이 쓸 수 있어야 합니다.

- 모집 회차(예: `2026-fall`)를 데이터에 포함시켜 학기별로 분리합니다.
- 날짜·장소·공개 시각은 운영진 화면에서 입력하며 서버에 저장합니다.
- 학기가 바뀌면 운영진 화면에서 새 회차를 만들고 날짜만 넣으면 됩니다.

## 검증

- 시크릿 탭에서 지원서 제출 → 정상 저장
- 남의 이름+전화번호로 `/api/me` 호출 → 그 사람 것만 나오고 다른 사람 정보는 없음
- 운영진 토큰 없이 `/api/admin/list` 호출 → 거부
- 발표 시각 전에 `/api/me` 호출 → 응답에 합격 여부가 **아예 없음**
  (빈 값이 아니라 필드 자체가 없어야 합니다)
- 브라우저 개발자도구에서 응답 본문을 확인해 불필요한 데이터가 없는지 점검
